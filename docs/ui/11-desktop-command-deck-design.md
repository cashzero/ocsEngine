## 1. 已確認範圍與設計假設

- 預設寬度 1920px；接受 1680px；移除窄螢幕需求。
- 一個左側 Command Deck，無右欄；地圖占剩餘空間。
- 整頁與整個左欄不垂直捲動；左欄只有「tab 區／任務區」一個捲動區。全部單位清單在 roster popup 內捲動。
- 一個模式最多一個主要捲動清單，不允許清單內再嵌套捲動清單（away report 在任務區內不再自帶捲動）。
- 1920×1080、1680×1050 是使用者確認的測試畫布；左欄實作寬度 400px，以真實內容驗證。
- 本稿中文為設計註解；產品目前英文介面不在這一步變更語系。
- 沿用現有原生 TypeScript、SVG 與遊戲公開介面。

Frontend thinking gate：既有戰棋工作台；核心旅程為設定、預覽同一作戰包、開始、合法行動、決策與交接、完成回合；資訊順序為階段與玩家、選取對象、合法行動、成本與結果。復原入口包含取消未提交選擇、重試、交接、暫停與存檔。主要風險為固定高度裁切、焦點遺失、候選過量、私密內容殘留。桌面以外不列設計目標。

## 2. 兩個畫布與版面

全寬頂部列高 64px；其下為 400px 左欄與地圖。地圖區：1920×1080 為 1520×1016，1680×1050 為 1280×986。

**頂部列**（左到右）：回合與天氣、玩家與目前 phase chip（hover／focus 時向下展開整個 Player Turn 的 phase 清單）、
`↶ Undo`（有可還原的步驟時）、**End phase**、目前座位、New Game／Pause／Session。
End phase 的標籤寫「Finish <目前步驟>」，副標「Next: <下一步>」；停用時由按鈕下方的提示說明原因

「Finish anyway: N units have not moved／Press again to confirm」，位置與大小規則不變（最壞約 301px 寬）。
交接進行中不顯示阻擋提示（交接面板已說明）。

**左欄**（由上到下，皆含邊框與間距）：

## 3. Tab、任務模式與狀態

### 3.1 Phase 專屬 tab

Tab 組合由當前 phase 與資料決定；必辦者在最左並帶徽章。每個 phase 的最後固定是 `Log`。

| 條件 | Tab |
|---|---|
| Reinforcement，或有待進場單位 | **Arrivals**（逐列選取後點藍色進場 hex） |
| Supply、Breakout，或有補給步驟 | **Supply**／**Breakout**（回收內部存量、編制追蹤路線、斷補單位餵養、突圍） |
| Aircraft Refit，或有可補給的 Air Base | **Refit** |
| Combat、Exploitation、Barrage | **Targets**（可攻擊／可砲擊的敵方 hex；空狀態說明原因） |
| 非 Aircraft Refit | **Unit**（模式、Release、燃料、卡車、傾倒等所選單位的動作） |
| 有可用空中任務 | **Air**（可選；排在 Unit 之後，不搶走該步驟的主要工作） |
| 一律 | **Log** |

切換規則：
- 換 phase 時回到該 phase 的第一個 tab；同一 phase 內玩家手動選的 tab 保留。
- 選到新單位時切到 Unit，但在 Arrivals／Supply／Refit 這類要逐列操作的 tab 中不切換。
- 單位清單與搜尋、Moved／Not moved 篩選在 `All units (n)` 開啟的 roster popup 中；開啟時焦點進搜尋框，關閉時回到按鈕。
- 不再有「Hex」tab；同一 Hex 的堆疊由地圖上的 stack picker 選。

### 3.2 任務模式

下列情況取代整個 tab 區（不顯示 tab 列），完成後回到原本的 tab 與捲動位置。順序固定為
**必須回答的 → 戰鬥結果卡 → away report**，使決策選項不被「發生了什麼」擠到第一屏之外：

- 交接（Hand over）、引擎的 pending decision（防守設定、損失、撤退、補給支付、先後手、空戰迎擊、任務回基地等）。
- 攻擊／砲擊／空襲草稿：參與者勾選、Lead 單選、事實與勝率提示、補給成本、規則阻擋原因、Cancel／執行。
- away report（對方回合期間發生的事）；戰鬥結果卡也可獨立出現在 tab 內容上方。

決策與草稿**不**做成 popup：內容量大，會遮住判斷所需的地圖，且供給支付、撤退、損失分配等不得被簡化的前置表單取代。
End phase 在任務模式中停用並說明原因。

### 3.3 移動確認 popup

選單位 → 地圖反白完整可達範圍（不設上限、不提供目的地清單）→ 點反白 Hex（或其上的棋子）→
**popup 貼在目的地 Hex**，內容：目的地、成本與剩餘 MP、「Move ends there」（ZOC／全 MP 地形／最小移動）、
超堆疊警告（4.8a）、引擎拒絕時的第一條規則原因（其餘「N more reasons」在 Unit tab 完整列出，且 Confirm 停用）、`Cancel`／`Confirm`。

- 位置：優先放在目的地之後；其次上下（不蓋住抵達路徑）；最後才是路徑側。避開縮放控制、圖例與 hover 資訊；
  目的地被拖出視窗時貼視窗邊緣、隱藏箭頭並滑開地圖覆蓋元件；有箭頭指向目的地中心。
- 開啟時焦點到 `Confirm`（Enter 確認）；Esc 取消並把焦點還給該 Hex。「再點同一 Hex 確認」的舊行為保留。
- 非 modal；與 roster、stack picker 互斥；交接時隨整個畫面一併清除。
- 點非合法 Hex 保留目前單位並提示原因。點選不立即提交。確認後保留單位與鏡頭，依新 revision 重新查詢；
  單位已無可移動範圍時自動取消選取。取消只清除 UI 草稿；已有引擎交易時必須用合法的取消交易操作。

### 3.4 狀態

- **S0 尚未選取**：選取列顯示「No unit selected」與開啟 `All units` 的提示；Unit tab 說明如何選單位，並在移動階段列出未移動單位數。
- **S1 多枚 Stack 與長名稱**：點棋子直接選到該單位；點 Hex 則開 stack picker（含敵方隱藏數）；roster 按編制分組、可搜尋。縮放、hover、選取框不得覆蓋印刷欄位。
- **S2 地圖移動**：見 3.3。
- **S3 複合行動**：見 3.2；成本或後果在草稿面板中不足以清楚呈現時，進入完整的行動審閱對話框並在該處提交，不得裁切或默默擴大捲動區。
- **S4 載入、失敗、空清單**：
  - 執行中：鎖定重複提交（End、Confirm、宣告按鈕停用），狀態列顯示「Working…」；不能把尚未接受的動作顯示為成功。
  - 失敗：保留選取與鏡頭，狀態列顯示原因與影響；不得顯示成「沒有合法行動」。
  - 真正空清單：各 tab 以一句話說明（例如「No enemy hex can be attacked.」「No Air Base has aircraft to refit.」）。
  - 過期候選：保留選取意圖、刷新可用項，要求重新確認，不自動提交改變後的選項。
- **S5 決策與交接**：

```text
┌───────────────── 全畫面隱私邊界 ──────────────────┐
│ Pass the screen to <required player>              │
│ [I am <required player>]                          │
└──────────────────────────────────────────────────┘
```

交接期間移除地圖、清單、tooltip、對話框與 accessible name 中的上一玩家私密內容；不能只靠遮罩。確認後依新玩家投影重建，
不帶入上一玩家的私密搜尋、選取、tab 記憶、roster 與 popup。Pending decision 依規則顯示選項、後果與擁有者；有合法取消選項才提供取消。

## 4. New Game 組合預覽

作為覆蓋遊戲的工作畫面，左右各留 24px，頂底各留 24px。設定欄 360px，主區使用剩餘寬度；無第三欄。

```text
┌────────────────────────────────────────────────────────────────┐
│ New Game · Configure / Review / Start                    Close │
├────────────────┬───────────────────────────────────────────────┤
│ Basic|Advanced │ 地圖預覽                  狀態 / 驗證清單       │
│                │                                               │
│ Style          ├───────────────────────────────────────────────┤
│ Width · Height │ Units · Formations · Deployment · Warnings     │
│ Scale          ├───────────────────────────────────────────────┤
│ Formations     │ Allied 摘要                 Axis 摘要           │
│ Turn limit     │ Allied | Axis · Formation filter               │
│                │ 共用棋子 renderer 的 unit 清單               ↕ │
├────────────────┴───────────────────────────────────────────────┤
│ Preview current / stale                  Build preview · Start │
└────────────────────────────────────────────────────────────────┘
```

在 1680×1050，對話框 1632×1002；預留標頭 64、底部 72，中段 866。主區預算：地圖 363、指標 56、雙方摘要與篩選 96、unit 清單 351。以上含邊框及內距，仍須驗證真實文字。1920×1080 增加的高度分配給地圖與清單。

Basic 保留必要選項，Width/Height 同列。Advanced 顯示四種 seed 與 Randomize。切換兩者不得重設輸入。預覽失效立即禁用 Start，仍可檢查帶有 stale 標示的舊預覽。生成中 Map/OOB/Deployment 狀態必須真實；不能以定時動畫假裝逐階段進度。預覽與啟動包必須保有現有整合契約。

Warnings 摘要持续可見；完整警告可作為主區清單的另一檢視，阻擋開局的原因直接出現在固定操作區。不能用一個警告數字取代阻擋原因。

## 5. 鍵盤、狀態與低頻操作

- Tab 在主要區域移動；地圖採單一焦點入口與方向鍵導航，Enter 選取／預覽，提供可見的清單替代入口（roster）。
- 清單採符合元件語義的鍵盤導航，不把所有 Hex 加入 Tab 序列。
- Escape 的順序：roster → 移動預覽 popup → stack picker → Session → New Game → 攻擊草稿 → 清除選取。
- DOM 更新後恢復相同控件或合理後繼焦點；隱藏頁籤不能保留可聚焦元素；popup 與 roster 開啟／關閉時依 3.1、3.3 搬移焦點。
- History 與 Checkpoint：事件在 `Log` tab；checkpoint 與 Save/Load/Pause 由 Session 對話框可達，關閉後回到原任務與位置。保留現有合法生命週期限制與復原流程。
- 視覺延續深綠工作面、克制的金色主操作；選取、警告、陣營與成功各有不同語義，不能只用顏色區分。
- 不以縮小一般文字低於 13px 解決空間不足；棋子圖稿沿用已有 LOD 與 full-detail 規範；tab 徽章另以 `aria-label` 提供數量。

## 6. 驗證狀態與後續

2026-10-02 的左欄重整（tab、任務模式、頂部 End phase、移動 popup、roster 焦點）已在內建瀏覽器以真實操作驗證：

防守與任務回基地決策、交接與 away report、超堆疊與「Move ends there」的 popup、目的地被拖出視窗、1680×1050 與 1920×1080 的無溢出檢查。
逐項紀錄、發現並修正的問題與觀察見 `docs/reports/left-panel-reorganization-2026-10-02.md`。

布局驗證同時檢查：容器無捲動、文字未裁切、hit target 可點、焦點可見、主要動作未被訊息覆蓋。`scrollHeight` 或 screenshot 單獨均不足以證明可用。清單切換後須保留位置，交接時則須清除私密上下文。

延遲沿用驗收基準：選取/查詢/鏡頭操作 ≤1000ms，執行 ≤1500ms，預覽/開始 ≤3000ms；超過 1000ms 不得無 busy state。實際觀察阻塞後再定位責任層，不預設 Worker 或框架遷移。
