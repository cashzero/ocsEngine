# Heuristic 策略（標準：heuristic@90）

## 範圍

標準電腦策略 `heuristic@90` 如何做決定：各階段做什麼、目標分配與移動評分、補給保護、戰鬥、重建與待決回應，
以及做過哪些嘗試、為什麼不採用。實作：`src/ai/policies/heuristic.ts`、權重 `src/ai/policies/heuristic-weights.ts`、
待決回應 `src/ai/decisions.ts`。介面與邊界見 [architecture.md](architecture.md)，強度量測見 [evaluation.md](evaluation.md)。

評估優先順序是 **VP > Kill > Loss**（使用者決定）：合法、完整打完與補給正確是前提，之後先看 VP，再看敵方損失與己方損失。
迫使敵方斷補是有效進攻手段；對局中出現斷補不代表策略有錯。

## 現行行為

### 每個階段

| 階段／segment | 行為 |
|---|---|
| Reinforcement | 先決定重建（見「重建與增援」），再放置增援 |
| Aircraft Refit | 選第一個合法 refit |
| Movement／Exploitation 的 Movement segment | 移動步驟（模式、燃料、HQ、卡車、鐵路、海運、一般移動）；Movement Phase 另可築 hedgehog |
| Barrage segment | Movement Phase 先派空中砲擊，再用砲兵；目標偏向主攻目標 |
| Combat segment | 從合法候選選期望值最高的攻擊（主攻目標加權） |
| Supply | 依價值排序餵養；用規則提供的共同口糧分組一次支付多個單位 |
| 任何時候有屬於自己的待決 | 由 `respondToDecision` 回答 |

沒有正分行動時才 `ADVANCE_SEQUENCE`，並在 trace 寫明理由。

### 目標分配（Movement segment 建立，存在當步驟的 `BotPhaseMemory`）

每次決策重新分析位置；主攻與任務分配於當 Movement segment 首次需要時建立，後續沿用當步驟記憶。每個單位得到一個任務：`CAPTURE`、`GARRISON`、`ASSAULT`、`HUNT`、`RESUPPLY` 或 `FRONT`。

- **分差價值**：取得中立目標點只讓己方 +VP；取得敵方持有的點同時讓己方 +VP、敵方 −VP，因此價值加倍。保護已持有的點同理。
  Trace 中把它標為 score-margin gain，不是實際取得的 VP。
- **敵方戰力估計**：看得到的單位用印刷戰力。疊在頂部之下看不到的 counter，每個以對方公開戰鬥序列的平均值計
  （地面單位的全戰力總和 ÷ 全部 counter 數，飛機與設施除外）；頂部不是戰鬥單位的 stack 底下沒有戰鬥單位（投影一定把戰鬥
  單位放在頂部），隱藏 counter 不加戰力（v75）。
- **先留守軍**：已持有的點先保留至少一個現有守軍；對手仍有後續回合時，繼續保留直到戰力達估計威脅的 0.5 倍或無人可留，再分配剩下的部隊。空點或受威脅的點補防權重較高。
  唯一守軍不會被派去追擊。己方持有但沒有戰鬥單位、且受威脅的點，在主攻選兵之前先保留一個本回合到得了（距離 ≤ MA）的
  最弱機動單位回防（v75）。
- **不能移動的單位**（MA 0：駐軍、部分工兵）只佔自己所在格的任務名額，不佔別處的守點或奪點名額（v75）。
- **主攻**：選有敵軍守備的目標點，12 格內可集結的兵力須達守軍估計的 2.5 倍（v75 前為 8 格）；派最近的單位（最多 6 個）
  組成攻擊群，接近時轉 Combat Mode、在目標旁集結。HQ 與卡車跟隨主攻。**攻擊戰的守方不組主攻**，不反攻攻方持有的
  目標點（v85，權宜做法；應只在有優勢時反攻，見 `bot-defender-counterattack`）。攻擊戰的攻方不用這裡的選法，改用下面的戰區配置。
- **戰區配置（v86）**：攻擊戰的攻方（權重 `theaterAllocation` 預設 1；設為 0 時照 v85 下）在每個 Movement 步驟以戰區配置（`src/ai/policies/theater.ts`）決定主攻與奪點：以本步驟與下一步驟的可達範圍（`projectedReach`，以移動時的模式計算；這一步不能移動又沒有燃料可付的單位留在原地）、`attackStrength` 的規則戰力與地形線型、估計的敵軍戰力、雙方最高 AR（看不到的守方以 2 計）與凍結的奪點機率模型，把非守點單位分給未持有目標，最大化點數乘以奪點機率（下一步驟才能到位的組再乘依 Game Turn 凍結的折扣）；每個組員在攻擊的那一步都要有補給：trace、可吃的現有 SP、配置指派的 HQ 投送，或配置指派的卡車這一步卸下的 SP（卸貨點可在 trace 外）；卡車依容量（每個 Transport Point 4T）、補給堆存量與 MA 計算，一組可用多輛，這一步跑救援的卡車不列入。被指派的 HQ 走向指定格；一個單位（集結者：下一步驟的組的成員，或沒被用到的單位）先停在卸貨點，被指派的卡車接著移動、移動當下選補給堆裝貨、送到卸貨點，然後其他戰鬥單位才移動；鐵路在計畫算入的裝貨格只留下被指派空車要裝的量；組員可離開 trace 到有 SP 可吃的攻擊位置，由卡車供應的組的成員可到卸下的 SP 供得到的任何格子。有守軍的組依期望 VP 依序成為主攻（沒被指派的 HQ 與卡車跟隨第一個主攻的領頭格），空目標的單位目標設為 CAPTURE，剩下的主攻名額沿用多回合的主攻選擇。設計與量測見[戰區補給配置](theater-supply-plan.md#策略上層)。
- **清除與追擊**：己方單位 5 格內戰力 ≤ 2 的敵方 stack（多為目標點駐軍，它的 ZOC 切斷 trace）列為清除目標；
  深入己方補給區或貼近己方目標點、HQ、補給堆的敵軍列為追擊目標。
- **撤回補給**：不在自己 trace 內、附近也沒有 SP 的戰鬥單位，除最後兩回合外撤回補給範圍；守著目標點的唯一單位在
  卡車可送補時留在原地。
- **最後一回合**：所有閒置單位改去奪取最近的未持有目標點，或守住最近的已持有點。

### 移動評分

每個（單位, 目的地）有分項分數；主要分項：

- **任務進度**：每格接近量 × 權重。目標點任務（CAPTURE／GARRISON／ASSAULT）用 15，其他任務用 10；CAPTURE／ASSAULT
  再乘上「目標 VP ÷ 地圖目標點平均 VP」（v66）。
- **當下可取得的 VP 優先**：能在目的地佔下目標點的移動先比 VP，再比其他分數（v17）。路過不停留只算 25%；
  最後一位玩家的最後一次移動沒有後續敵方回合，路過也算全額，並取消守點與離點的分項（v59）。
- **威脅**：一般以 4 格內敵方戰力估計。已持有的目標點另外加上可見敵軍沿公開道路、地形與目前天氣在下一次（若己方先動，
  則兩次）移動內可能到達的強度（規則投影的 `objectiveRaidThreats`）；不讀敵方燃料、隱藏單位或移動紀錄，
  未知的燃料與架橋採樂觀估計。
- **補給**：離開 trace −60；目的地 2 格內有可分配的 SP 時減為 −10；只靠 HQ 投送的格子 −8。
- **其他**：同格擁擠、砲兵需在 3 格內與戰鬥單位同格（否則 −40）、HQ 與砲兵暴露、卡車與後方單位暴露、Strat Mode 距敵距離。
- HQ 先移動，因為它的投送範圍決定其他單位哪裡有補給。急需的送補先於一般部隊移動。
- **HQ 的補給鏈**（heuristic@79，OCS 的 rail → HQ → 投送）：
  - 不離開鐵路的取用範圍（使用者決定：HQ 的核心目的就是提供補給）：目的地既沒有補給堆能供應它（自己的投送不算，12.3b），
    也不在任何車站的取用範圍（5 Truck MP 加相鄰格，12.3a、12.3c，規則層 `queryDrawReach`）內時 −80。車站是鐵路上的
    村鎮城市與站著 Combat Mode HQ 的鐵路格，離敵 3 格以上且在 trace 內；鐵路在 HQ 之後才動，把 SP 送到這些車站，HQ 就能取用。
    HQ 不必站在鐵路上。
  - 分區：每個 HQ 每多投送到一點前線戰力（離敵 6 格內、HQ 以外的戰鬥單位，投送距離取印刷射程的 3/4 格、至少 3 格）+1，
    但不算同一步驟中先移動的 HQ 已投送到的單位，所以各 HQ 分開照顧不同部隊，而不是都跟著同一點；不在取用範圍時只算一半。
  - 已經站在離敵 3 格以上鐵路格上、部隊在 6 格內的 HQ 開始移動時改為（或維持）Combat Mode 不動，該格成為車站（13.8c）。


### 後勤

- **卡車**（heuristic@78）：每輛卡車在 Movement Segment 內循環「取貨 → 送達 → 回程」，動作連續執行（6.1g），
  直到 MP 用完。
  - 取貨：前往離敵 5 格以上、不在目標點、不是駐軍存量、本步驟沒有卸下或運到 SP（12.2a）的後方補給堆，
    依空車里程加載貨里程、扣掉載量估價；其他卡車已預約的 Token 不算。到達後從格內每個可裝的堆裝滿；
    部分載貨的卡車停在後方堆時先補滿。當步驟到不了取貨點（或到了沒有裝貨的 5 MP）的卡車放棄預約，留給到得了的卡車。
  - 只在有比所在格更靠近部隊中心的卸貨點時才裝貨：沒有可送的地方時，裝了也只能在原地卸下。
  - 送達：卸貨點要有己方戰鬥單位或補給堆（13.2f）、離敵 3 格以上、在己方 trace 範圍內（卡車不跑到補給線外被切斷）。
    以規則層的移動範圍與剩餘 MP 判斷能否到達並留下卸貨的 MP（印刷 MA 的 10%），選最靠近部隊中心
    （主攻的 lead，否則部隊重心）的點。最佳點到不了時，若到得了的點比所在格靠近中心至少 4 格就先卸在那裡（接力）；
    否則載貨朝最佳點前進並結束。
  - 回程：卸貨後用剩下的 MP 前往下一個取貨點，到得了就再裝一車，下一回合從補給堆出發。
  - 被切斷的單位群（戰力 ≥ 6）仍優先由一輛載貨卡車送補（heuristic@7）；有未指派的救援目標時，空車只裝 2T 送去。
  - **補缺口**（heuristic@79）：卡車最後移動。想移動、需要燃料（12.5a）卻沒有任何合法加油方式的戰鬥單位記為「受困」；
    沒有補給堆供應的 HQ 記為「乾 HQ」，價值是它能投送到的前線戰力。送貨中心改為受困戰力加乾 HQ 價值最大、3 格內有安全卸貨點的
    位置，卸在那裡後附近的受困單位與取用範圍內的乾 HQ 視為已補；都沒有時才送往主攻 lead 或部隊重心。
  - 狀態以每輛卡車一個「取貨／送達／救援／結束」的階段表示（`TruckLeg`），每個動作明確轉到下一個階段。
  - heuristic@75 及更早：每輛卡車每步驟最多裝一次、移動後只能卸貨、卸貨後不再移動，到不了卸貨點的卡車載貨停住，
    入場格的 SP 逐回合累積（[量測](evaluation.md#攻方運補-gate)）。
- **鐵路**（heuristic@12）：用 Rail Cap 把後方車站的 SP 與遠方單位送到離敵 3 格以上、最靠前線的車站，收益大的先送。
  heuristic@79：鐵路與海運等所有 HQ 動完才動（HQ 的 Combat Mode 先讓鐵路格成為車站）；卸到 HQ 取用範圍（`drawReach`）內、
  而出發地不在範圍內的 SP 每 SP 加 10 格的價值，即使朝前線不到 3 格也送。
- **新到的 SP 先放鐵路**（heuristic@79）：增援階段新到的 SP 優先放在有鐵路的入場格，當回合就能上火車（13.6b）；
  其他入場格只能由卡車從地圖邊緣拉。v78 攻方地圖上約 32 SP 中只有約 7 SP 在能上火車的格子。
- **海運**：Box 中等待的先上岸（戰鬥單位先於 SP），再把遠離前線港口的貨物移到較近的港口。
- **Hedgehog**（heuristic@10）：所有單位移動後，留在敵軍附近的單位築 hedgehog：先已持有的目標點，再其他鄰接敵軍的格；
  補給堆扣掉一級的 8T 後仍須保留儲備，且不破壞口糧承諾。
- **空軍**：只派 Air Barrage 打己方單位相鄰或主攻目標的戰鬥單位，並在 Refit Phase refit；其他任務與空中待決見「已知缺口」。
- **設施砲擊**：砲兵把港口、機場與戰鬥單位的收益放在一起比較。設施使用獨立的 Facility Table 預測，規則見
  [artillery.md](../rule-engine/artillery.md)。

### 補給保護

補給預判由規則層計算（[architecture.md](architecture.md)）。保護的是目前位置與存量下的供補，不保證敵方之後不切斷路線，
也不預支未來到達的補給。

| 行動 | 限制 |
|---|---|
| 一般移動、切模式 | 不讓任何目前有 trace 的己方單位失去 trace，也不減少任何既有 SP 消費者的口糧（含卡車載運的影響）；沒有安全選項就留在原地 |
| 可選補給支出（燃料、hedgehog） | 支出後共同口糧計畫仍能履行既有承諾；強制的內部存量恢復先扣，且沒有 trace 的單位靠強制恢復達到的內部存量等級不能因支出而下降（`supply.recoveryLoweredUnits`）：否則它既不能恢復也不在口糧計畫中，Supply 時受 attrition（12.10e、12.6c；[錯誤清單 E2](policy-errors.md)） |
| 設施砲擊 | 第一位玩家回合的 Reaction 中，非主動方尚有同回合的 Supply，宣告與每次實際付款都保留共同口糧承諾；改選安全的合法補給來源，沒有安全路徑就不射擊。Combat、Exploitation 與第二位玩家回合的 Reaction 不重複預留已結束的當回合 Supply |
| 一般戰後前進 | 第一個進入敵方格的單位也檢查共同口糧與 trace；奪點時選有補給的最強單位；補強已奪下且受威脅的點時只用不造成任何 trace／口糧損失、自己仍有 trace 的單位 |
| Overrun | 以清空目標且進攻者存活為條件預判，計入宣告成本與內部存量消耗；不預支隨機俘獲的 SP |
| 最後一次補給階段之後 | 不為不存在的下一頓預留口糧，其他 trace 保護照常 |
| 撤退 | 依序比較：必受損失、無口糧單位數、trace 中斷數，再比敵方威脅 |

- **共同口糧**：每個單位只由一個可達來源支付，同來源的 RE 合計後進位；Supply 階段送出群組 `CHECK_SUPPLY`。
  不足時依 HQ、戰鬥單位、其他的優先序。分配搜尋上限 50,000 個節點，超過時回報未知而不是無解。
- 下一次友方 Supply 的預判會清除已付的補給、已恢復的內部存量、空投豁免與已結束戰鬥的暫存承諾。

### 戰鬥與砲擊

- 以公開 Combat Table 計算 2d6 的結果分布（不含 Surprise），攻擊門檻權重 4；Overrun 門檻是一般攻擊的兩倍。
  除最後一回合搶目標點外不打 1:1 以下。
- **從持有點出擊的風險**（v75）：攻擊者站在己方持有的目標點上、且留下的戰力低於該點威脅 × holdRatio，而敵方之後還有
  回合時，扣分「攻擊者損失或 option 的期望值（上限 1）× 該點分差 VP × 25 × 0.25 × 出擊戰力占比」。
- 砲兵對戰鬥單位的評分包含 DG、步損、補給成本、目標點與主攻目標，己方單位相鄰時提高 DG 收益。
  空中砲擊只打主攻目標或己方單位相鄰的敵軍；每格每階段仍只能受一次砲擊（10.0e）。

- 模式只為戰鬥單位與 HQ 改變：砲兵維持部署時的模式（多為 Move Mode），以 Move 面約一半的砲擊戰力射擊；砲擊分數為 DG 機率 × 10（目標旁沒有己方單位時 × 4）＋ 預期損失步數 × 10 − Token × 1.2，門檻 2。

設施砲擊逐一計算 Facility Table 的六個等機率結果，再扣除實際供補成本。港口收益包括四次損壞上限與取整後的
容量減少，乘上剩餘敵方海運回合；只有情境宣告為 Supply Source 的港口，跨過 4T 門檻才另計斷補收益。
機場收益包括最低 Level 1 以上可失去的 refit 容量，以及目前看得到的敵機之獨立檢定期望步損。
沒有後續敵方回合就不計容量收益。Air Strip 不計等級損失，隱藏 counter 不當作飛機，敵方 SP 餘額與未來骰值不參與評分。

`findBarragePaymentPlan` 重用實際付款選項與預留邏輯，搜尋完整的合法路徑。它只試扣己方資源，不結算目標、不擲骰。
失敗預留狀態會快取；已破壞共同口糧承諾的分支不再往下搜尋。宣告可行後，待決付款仍使用相同檢查選安全來源。
戰鬥單位砲擊沿用上游策略的結果預測與補給評分。設施砲擊的補給分項仍按實際全額成本計算，不宣稱一般策略強度提升。

### 重建與增援

- **重建**：每個合法重建位置比較：受威脅且守備不足的己方 VP 點優先，其次是補齊 formation 唯一的 HQ、可移動單位、
  印刷戰力的增量。已消滅的固定單位只在己方 VP 點或原位置重建；重建後無法由補給支付的固定單位會被移除（v19）。
  13.5d 成對列由規則計價。
- **重建準備**（剩餘超過 3 回合）：Move Mode 的 HQ 旁 2 格內有未用的 Repl，且有可重建的機動單位或同格減員單位時，
  HQ 改回 Combat Mode 以便下回合重建（不破壞任何 trace）。
- **增援**：Combat／HQ／Artillery 優先放在自己有 trace 的入場格，再比距離目標與威脅；Repl 放在 HQ 2 格內。

## 決策

### 採用

- 以重播研究改策略，不以權重自我對戰調參（使用者決定）：四代訓練都沒有顯著改善，勝負差異落在雜訊內，
  而重播顯示輸的原因是結構性的（空目標點、斷補）。
- 先修電腦自己破壞補給的行為，再改進攻（使用者決定）。補給保護一律用規則層的真實預判，並以實際 reducer 核對。
- 目標點以分差計價（v61）；目標點任務的進度依目標 VP 加權（v66）。
- 隱藏 counter 以對方公開戰鬥序列估值（v75）：舊估計把每個隱藏 counter 當成一個平均可見戰鬥單位，但隱藏的多半是補給堆、
  卡車、HQ、砲兵與補充。對 10,214 個有隱藏 counter 的 stack 與真實戰力比較：舊估計平均高估 11.8、平均誤差 14.2，
  新估計平均低估 0.7、平均誤差 5.0。高估讓攻擊方在有守軍的目標點前兩格停下、主攻從第 3 回合起不再成立。
- 主攻集結範圍 12 格（v75）：目標點常在敵軍防線後 10–20 格，8 格內湊不出攻擊群，單位只能各自前進。
- 卡車循環運補（v78）：v75 的卡車卸貨後不再移動，入場格的 SP 逐回合累積，攻方的補給短缺來自電腦而不是運輸能力。
  v78 未達 VP 升級門檻，由使用者破例升級，理由見 [evaluation.md 決策](evaluation.md#決策)。
- 補給鏈 rail → HQ → 投送（v79）：v78 的 SP 多半不在能上火車的格子、HQ 都跟著同一點，攻方約四分之一需要燃料的單位加不到油。
  HQ 不必站在鐵路上，但不能離開車站的取用範圍（使用者：HQ 的核心目的就是提供補給）；取用範圍用規則層的 `queryDrawReach`，
  不用格數估計（2 格估計只把無法加油降到每局 16.4，規則的 5 Truck MP 降到 5.9）。v79 未跑獨立批，由使用者決定直接升級。

- 攻擊戰的守方不反攻（v85，使用者決定直接升級，未跑獨立批）：v79 的守方不分有無優勢都反攻，[局面接續測試](../quality/evidence/ai-defender-assault-continuation-2026-10-18/README.md)
  中拿掉反攻，守方每局少損失 2.5 ± 0.7 step、VP 差 +1.9 ± 0.9；代價是攻方斷補的單位變少。這是權宜做法，只在有優勢時反攻是
  `bot-defender-counterattack`。v85 同時帶有對港口與機場的砲擊（`7990052`，沒有 VP 對戰量測）。v81–v83 的分角色主攻規劃已刪除

- 攻擊戰的攻方以戰區配置規劃（v86，使用者決定例外升級，2026-11-13；只用西歐攻擊戰的事先登記觀測，未跑升級流程的獨立批，

## 已知缺口
