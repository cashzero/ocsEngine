# Heuristic 策略（標準：heuristic@66）

## 範圍

標準電腦策略 `heuristic@66` 如何做決定：各階段做什麼、目標分配與移動評分、補給保護、戰鬥、重建與待決回應，
以及做過哪些嘗試、為什麼不採用。實作：`src/ai/policies/heuristic.ts`、權重 `src/ai/policies/heuristic-weights.ts`、
待決回應 `src/ai/decisions.ts`。介面與邊界見 [architecture.md](architecture.md)，強度量測見 [evaluation.md](evaluation.md)。

評估優先順序是 **VP > Kill > Loss**（使用者決定）：合法、完整打完與補給正確是前提，之後先看 VP，再看敵方損失與己方損失。
迫使敵方斷補是有效進攻手段；對局中出現斷補不代表策略有錯。

## 現行行為

### 每個階段

| 階段／segment | 行為 |
|---|---|
| Reinforcement | 先決定重建（見「重建與增援」），再放置增援 |
| Aircraft Refit | 選第一個合法 refit |
| Movement／Exploitation 的 Movement segment | 移動步驟（模式、燃料、HQ、卡車、鐵路、海運、一般移動）；Movement Phase 另可築 hedgehog |
| Barrage segment | Movement Phase 先派空中砲擊，再用砲兵；目標偏向主攻目標 |
| Combat segment | 從合法候選選期望值最高的攻擊（主攻目標加權） |
| Supply | 依價值排序餵養；用規則提供的共同口糧分組一次支付多個單位 |
| 任何時候有屬於自己的待決 | 由 `respondToDecision` 回答 |

沒有正分行動時才 `ADVANCE_SEQUENCE`，並在 trace 寫明理由。

### 目標分配（每次決策重算，存在當步驟的 `BotPhaseMemory`）

每個單位得到一個任務：`CAPTURE`、`GARRISON`、`ASSAULT`、`HUNT`、`RESUPPLY` 或 `FRONT`。

- **分差價值**：取得中立目標點只讓己方 +VP；取得敵方持有的點同時讓己方 +VP、敵方 −VP，因此價值加倍。保護已持有的點同理。
  Trace 中把它標為 score-margin gain，不是實際取得的 VP。
- **先留守軍**：已持有的點先依威脅保留守軍（空點或受威脅的點權重較高；一個守軍，受威脅時兩個），剩下的單位才分配出去。
  唯一守軍不會被派去追擊。
- **主攻**：選有敵軍守備的目標點，8 格內可集結的兵力須達守軍估計的 2.5 倍；派最近的單位（最多 6 個）組成攻擊群，
  接近時轉 Combat Mode、在目標旁集結。HQ 與卡車跟隨主攻。
- **清除與追擊**：己方單位 5 格內戰力 ≤ 2 的敵方 stack（多為目標點駐軍，它的 ZOC 切斷 trace）列為清除目標；
  深入己方補給區或貼近己方目標點、HQ、補給堆的敵軍列為追擊目標。
- **撤回補給**：不在自己 trace 內、附近也沒有 SP 的戰鬥單位，除最後兩回合外撤回補給範圍；守著目標點的唯一單位在
  卡車可送補時留在原地。
- **最後一回合**：所有閒置單位改去奪取最近的未持有目標點，或守住最近的已持有點。

### 移動評分

每個（單位, 目的地）有分項分數；主要分項：

- **任務進度**：每格接近量 × 權重。目標點任務（CAPTURE／GARRISON／ASSAULT）用 15，其他任務用 10；CAPTURE／ASSAULT
  再乘上「目標 VP ÷ 地圖目標點平均 VP」（v66）。
- **當下可取得的 VP 優先**：能在目的地佔下目標點的移動先比 VP，再比其他分數（v17）。路過不停留只算 25%；
  最後一位玩家的最後一次移動沒有後續敵方回合，路過也算全額，並取消守點與離點的分項（v59）。
- **威脅**：一般以 4 格內敵方戰力估計。已持有的目標點另外加上可見敵軍沿公開道路、地形與目前天氣在下一次（若己方先動，
  則兩次）移動內可能到達的強度（規則投影的 `objectiveRaidThreats`）；不讀敵方燃料、隱藏單位或移動紀錄，
  未知的燃料與架橋採樂觀估計。
- **補給**：離開 trace −60；目的地 2 格內有可分配的 SP 時減為 −10；只靠 HQ 投送的格子 −8。
- **其他**：同格擁擠、砲兵需在 3 格內與戰鬥單位同格（否則 −40）、HQ 與砲兵暴露、卡車與後方單位暴露、Strat Mode 距敵距離。
- HQ 先移動，因為它的投送範圍決定其他單位哪裡有補給。急需的送補先於一般部隊移動。

### 後勤

- **卡車**：在後方補給堆裝至少 8T，送到部隊中心或主攻附近卸下，再回頭載下一批；被切斷的單位群（戰力 ≥ 6）由一輛卡車送補。
- **鐵路**（heuristic@12）：卡車移動前，用 Rail Cap 把後方車站的 SP 與遠方單位送到離敵 3 格以上、最靠前線的車站，收益大的先送。
- **海運**：Box 中等待的先上岸（戰鬥單位先於 SP），再把遠離前線港口的貨物移到較近的港口。
- **Hedgehog**（heuristic@10）：所有單位移動後，留在敵軍附近的單位築 hedgehog：先已持有的目標點，再其他鄰接敵軍的格；
  補給堆扣掉一級的 8T 後仍須保留儲備，且不破壞口糧承諾。
- **空軍**：只派 Air Barrage 打己方單位相鄰或主攻目標的戰鬥單位，並在 Refit Phase refit；其他任務與空中待決見「已知缺口」。

### 補給保護

補給預判由規則層計算（[architecture.md](architecture.md)）。保護的是目前位置與存量下的供補，不保證敵方之後不切斷路線，
也不預支未來到達的補給。

| 行動 | 限制 |
|---|---|
| 一般移動、切模式 | 不讓任何目前有 trace 的己方單位失去 trace，也不減少任何既有 SP 消費者的口糧（含卡車載運的影響）；沒有安全選項就留在原地 |
| 可選補給支出（燃料、hedgehog） | 支出後共同口糧計畫仍能履行既有承諾；強制的內部存量恢復先扣 |
| 一般戰後前進 | 第一個進入敵方格的單位也檢查共同口糧與 trace；奪點時選有補給的最強單位；補強已奪下且受威脅的點時只用不造成任何 trace／口糧損失、自己仍有 trace 的單位 |
| Overrun | 以清空目標且進攻者存活為條件預判，計入宣告成本與內部存量消耗；不預支隨機俘獲的 SP |
| 最後一次補給階段之後 | 不為不存在的下一頓預留口糧，其他 trace 保護照常 |
| 撤退 | 依序比較：必受損失、無口糧單位數、trace 中斷數，再比敵方威脅 |

- **共同口糧**：每個單位只由一個可達來源支付，同來源的 RE 合計後進位；Supply 階段送出群組 `CHECK_SUPPLY`。
  不足時依 HQ、戰鬥單位、其他的優先序。分配搜尋上限 50,000 個節點，超過時回報未知而不是無解。
- 下一次友方 Supply 的預判會清除已付的補給、已恢復的內部存量、空投豁免與已結束戰鬥的暫存承諾。

### 戰鬥與砲擊

- 以公開 Combat Table 計算 2d6 的結果分布（不含 Surprise），攻擊門檻權重 4；Overrun 門檻是一般攻擊的兩倍。
  除最後一回合搶目標點外不打 1:1 以下。
- 砲擊只打主攻目標或己方單位相鄰的敵軍；空中砲擊先選主攻目標，砲兵打下一個（每格每階段一次砲擊，10.0e）。

### 重建與增援

- **重建**：每個合法重建位置比較：受威脅且守備不足的己方 VP 點優先，其次是補齊 formation 唯一的 HQ、可移動單位、
  印刷戰力的增量。已消滅的固定單位只在己方 VP 點或原位置重建；重建後無法由補給支付的固定單位會被移除（v19）。
  13.5d 成對列由規則計價。
- **重建準備**（剩餘超過 3 回合）：Move Mode 的 HQ 旁 2 格內有未用的 Repl，且有可重建的機動單位或同格減員單位時，
  HQ 改回 Combat Mode 以便下回合重建（不破壞任何 trace）。
- **增援**：Combat／HQ／Artillery 優先放在自己有 trace 的入場格，再比距離目標與威脅；Repl 放在 HQ 2 格內。

### 待決回應（`src/ai/decisions.ts`）

| 待決 | 選擇 |
|---|---|
| FIRST_PLAYER | 最後一回合、或 VP 落後時（遭遇戰任何回合；攻擊戰只在倒數第二回合）選後手；其他選先手 |
| SUPPLY_SOURCE | 能付全額的最滿補給堆；沒有補給堆時用內部存量 |
| DEFENDER_LEAD／DEFENDER_TERRAIN | 對攻方 DRM 或勝率最不利的選項（解析 `−`、`-`、`+`） |
| STEP_LOSS／ATTRITION_LOSS／OVERSTACK_ELIMINATION | 價值最低的單位 |
| OPTION_SPLIT | 守目標點時少退優先；其他時候少損失優先 |
| RETREAT_HEX | 見「補給保護」的撤退順序 |
| DISPLACEMENT_HEX | 敵方威脅最低的格 |
| ADVANCE_HEX | 見「補給保護」；不讓持有點的唯一守軍前進；非目標點只在威脅 < 8 時前進 |
| BREAKDOWN_ABSORPTION | 每 step 價值最高的單位 |
| 空中待決與其他 | 第一個合法選項，trace 標 `first-option` |

## 決策

### 採用

- 以重播研究改策略，不以權重自我對戰調參（使用者決定）：四代訓練都沒有顯著改善，勝負差異落在雜訊內，
  而重播顯示輸的原因是結構性的（空目標點、斷補）。
- 先修電腦自己破壞補給的行為，再改進攻（使用者決定）。補給保護一律用規則層的真實預判，並以實際 reducer 核對。
- 目標點以分差計價（v61）；目標點任務的進度依目標 VP 加權（v66）。

### 試過但不採用（不要再以相同方式重試）

| 嘗試 | 結果 | 原因 |
|---|---|---|
| 「避免落單」扣分 | 被逐一擊破的比例不變 | 需要戰線規劃，不是單一扣分 |
| 攻堅集結加分（無補給支撐） | 對 v2 6:10 | 部隊被斷補撤回拉回；攻堅要 HQ、補給與攻擊群一起推進 |
| 砲兵護衛 4 格 | 砲兵退到射程外，砲擊減少 | 改為 3 格 |
| 運補依共同口糧缺口排序（v20） | 可救援的駐軍改為吃不到 | 運補要同時規劃駐軍與機動部隊 |
| 戰鬥先比 VP 再比分數（v21） | 24 場 −44 VP | 非 VP 戰鬥常在保護已持有的點或補給線 |
| 只在最後回合先比 VP（v22）、增援先選有 trace 的格（v23） | VP 持平 | 無改善 |
| Pax／Eq 入場以 HQ 2 格為條件（v24） | 獨立批 −18 VP | 距離不代表當下能重建 |
| 調高 VP 任務進度到 20（v39）或降到 12（v41、v42） | −20 VP；獨立批 −22 VP | 太激進／太保守 |
| 所有移動都套用遠距道路威脅（v43） | −28 VP | 進攻過度保守；只用在已持有的點 |
| 最後三回合限制追擊（v48） | −18 VP | 遠方切補給的機會也影響 VP |
| 只檢查移動者 trace、放寬一般移動（v49） | 駐軍送補失敗 | 恢復零 trace／零口糧損失的限制 |
| 攻擊戰改用 v47 的守點分配（v56） | 同種子 −16 VP | 不能把不同批次的增益相加推論 |
| 前五回合不因落後改選後手（v62） | 同種子 −66 VP | 保留 v61 的先後手 |
| 主攻名額扣除 ASSAULT／GARRISON（v63、v64） | 同種子少 50 VP | 名額正確不代表打得更好 |
| 主攻選兵改以「戰力 ÷ 到達時間」排序（v65） | 同種子少 38 VP | 恢復最近優先 |

各次嘗試的種子與數據在 git 歷史的舊報告與 `docs/quality/evidence/ai-*` 的文字紀錄中。

## 已知缺口

以下 TODO 的缺少行為、影響與關閉證據見 [05-todo-inventory.md](../quality/05-todo-inventory.md)：

- `bot-air`：只派 Air Barrage 與 refit；其他任務、空運、空降、建 Air Base 不做，空中待決選第一個選項。
- `bot-stack-move`：逐一移動與 overrun，不整疊行動。
- `consolidation-bot`：不合併單位。
- `bot-ration-search`：共同口糧搜尋有節點上限。
- `GS-AI`：完整對局中仍有可救援的駐軍餓死。
- `ai-vp-plan`：重建準備只用剩餘回合門檻；動作後 trace 修正只查前 12 個候選；首次進入有敵方運輸單位的前進與 Overrun
  後強制進駐的補給風險未預判；`DISPLACEMENT_HEX` 不看補給。
- `bot-eastern-front`、`bot-offensive-axis`：東歐地圖與有補給支撐的主攻方向。
- 沒有 Reserve、Reaction 反擊、Extender、Breakout 規劃；戰鬥預估不含 Surprise。
