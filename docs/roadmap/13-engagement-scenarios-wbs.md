# 劇本 0.5.0：拉近遭遇戰、加入攻守劇本

狀態：**IN PROGRESS**（2026-10-07 建立）。S1–S7 完成；SCN-R3 有 1 個 seed 未達標（§5 TODO）。

需求來源（使用者，2026-10-07）：「目前的劇本是遭遇戰 但我覺得初始距離過遠 請拉近。並且加入一方進攻一方防守的不對稱劇本配置。
先關注溫帶地圖就好 東歐地圖先不管了」；之後補充：「進攻方兵力要比較多吧 至於是1.5倍還是2或3 看你」、
「但進攻的劇本 防守方開場要佔據更多土地」、「可以加入off map 空軍」。
使用者決定（2026-10-07）：地圖外空軍只給進攻方；先完成攻守劇本（兵力、土地、平衡、瀏覽器驗證），再另開一步做地圖外空軍（§2 S7）。

## 0. 現況（改版前量測）

- 部署以各自地圖邊緣的進場格為錨點，越靠近己方地圖邊緣越優先；補給堆放在進場格往內 3 格。
- 預設 New Game（32×24 溫帶、每方 6 師）seed 0–9：每個 Allied 地面單位到最近 Axis 單位的距離，最小 19–22 格、中位數 23–27 格、最大 26–29 格。
- 勝負：終局時持有目標 VP 較多的一方獲勝，相同為和局；雙方開局持有相同 VP。

## 1. 設計（數值依驗證結果調整，記錄在 §4）

地圖由西（Allied）到東（Axis）。雙方區域以「一格離雙方進場錨點的距離差」劃分（遭遇戰為 0，即沿用舊分區）；
一格的「縱深」= 它到分界的格數（己方那一側）。

| 項目 | 遭遇戰（MEETING，預設） | 攻守戰（ALLIED_ATTACKS／AXIS_ATTACKS） |
|---|---|---|
| 分界 | 地圖正中 | 往進攻方偏移，守方區域約佔 70% |
| 兵力 | 雙方師數相同、戰力差 ≤ 10% | 攻方師數為 1.5 倍（含裝甲師），戰力平衡以 1.5 : 1 為目標（差 ≤ 10%） |
| 戰鬥單位 | 雙方由縱深 ≥ 4 的格子由前往後部署（不再貼地圖邊緣） | 守方：縱深 ≥ 1 由前往後，**戰鬥模式**；攻方：縱深 ≥ 3 由前往後，移動模式 |
| 補給堆 | 戰鬥單位後方（縱深較深處），仍以補給範圍涵蓋最大為優先 | 同左 |
| 目標 | 雙方各持相同 VP（不變） | 全部在守方區域、由守方持有並駐守；VP 總數與遭遇戰雙方合計相同 |
| 駐守單位 | 每個目標 1 個（不變） | 攻方沒有（不持有目標）；守方每個目標 1 個，另在非 VP 的關鍵點各放 1 個：補給節點（鐵路接到己方地圖邊緣的可下車城鎮）優先，再來是道路交會點（≥ 3 條道路）；數量為目標數的一半（無條件進位），彼此及與目標相距 ≥ 3 格、在守方起始線後、離前線近者優先；一格只放一個 |
| 勝負 | 不變 | 攻方終局持有 ≥ 一半目標 VP 即勝，否則守方勝（無和局；劇本專屬勝利條件） |
| 第一回合先手 | Allied（不變） | **進攻方**（劇本資料；之後回合照常擲骰） |

兵力倍數（1.5、2 或 3）由 §2 S4 的電腦互打結果決定，結果與理由記錄在 §4。

## 4. 實作與量測紀錄

### 部署（S1、S2）

- `NewGameRequest.engagement`：`MEETING`（缺省）、`ALLIED_ATTACKS`、`AXIS_ATTACKS`；未知值以 `UNKNOWN_ENGAGEMENT` 拒絕。
  遭遇戰的 Scenario ID 不變，攻守戰在 ID 後加 `:allied-attacks`／`:axis-attacks`。
- 分界沿用舊的「離雙方進場錨點距離差」：遭遇戰為 0（與舊分區完全相同，所以鐵路控制與目標所在區不變）；
  攻守戰往攻方移動兩錨點距離的 40%（使用者：「防守方開場要佔據更多土地」），預設地圖守方 528 格、攻方 240 格（69%）。縱深 = 距離差 ÷ 2。
- 戰鬥單位由縱深 ≥ 起始線（遭遇戰 4、攻方 3、守方 1）的格子由前往後排列，比縱深淺的格子排最後。
- 補給堆放在起始線後 ≥ 2 格，從離起始線最近的 40 個候選格中，選「取補範圍內同時能 trace 的格子」最多者。
- **開局補給**：第一版只要求部隊在補給堆範圍內，結果有些 seed 一方只有 29–41% 的單位在 trace 內（部隊集中在沒有鐵路城鎮的角落）。
  改為部署時估計 trace 範圍（己方地圖邊緣來源，以及沿鐵路不離開己方區域就能連到的可下車城鎮，各自 5 卡車 MP 與相鄰格），
  編隊中心先選「補給堆範圍且在 trace 內」的格子，額外溢出的單位也優先放在這些格子。
- 守方的戰鬥、偵察、獨立裝甲、反坦克、工兵單位開局為戰鬥模式（戰鬥面）；砲兵、HQ、卡車照舊。
- 第一回合先手：攻守戰由攻方先手（`turnStart.firstPlayerId`），之後回合照常擲骰；遭遇戰維持 Allied。

### 攻守平衡（S4，溫帶、預設 32×24、每方 6 師、heuristic@5 互打，每種 20 局）

攻方勝率依序試過以下設定；一律 0 錯誤、全部打完、replay 相符。

| 設定 | seed | Allied 進攻：攻方勝-守方勝-和 | Axis 進攻：攻方勝-守方勝-和 | 攻方合計 |
|---|---|---|---|---|
| 兵力相同、守方區域 60%、「VP 多者勝」 | 34000／34500 | 5-15-0 | 5-14-1 | 10/40 |
| ＋ 守方三分之一師第 3 回合才進場 | 同上 | 4-14-2 | 7-13-0 | 11/40 |
| ＋ 守方一半師第 4 回合才進場 | 同上 | 3-13-4 | 6-11-3 | 9/40 |
| **攻方師數 1.5 倍、守方區域 70%、攻方 ≥ 一半 VP 即勝** | **36000／36500（新 seed）** | **9-11-0** | **9-11-0** | **18/40（45%）** |

- 前三列的攻方平均終局 VP 3.6–5.5（共 12 VP），很少超過 6，所以「超過一半才贏」幾乎達不到；延後守方進場只讓 VP 略增。
  守方預備隊方案已移除，改依使用者「進攻方兵力要比較多」給攻方 1.5 倍師數（含裝甲師；預設 9 師對 6 師），
  戰力平衡目標改為 1.5 : 1（預設 seed：Allied 進攻 296 : 179、Axis 進攻 290 : 211）。補給也隨師數增加。
- 勝利條件改為劇本專屬：攻方終局持有 ≥ 一半 VP（`ceil(總 VP / 2)`）即勝，否則守方勝（`RuleConfiguration.attackVictory`）。
- 最後一列：攻方平均每局經攻擊奪下有守軍的目標 3.35（Allied）／3.40（Axis）次（SCN-R5 要求 ≥ 1）。
  攻方最大的損失仍是斷補消耗（每局 6–8 step），這是電腦的弱點，不影響劇本本身。
- 1.5 倍已讓攻方勝率落在 30%–70%，所以不再試 2 倍或 3 倍。

## 6. S7 地圖外空軍（只給攻方）

需求：「可以加入off map 空軍」；使用者決定只給進攻方，攻守劇本完成後再做（2026-10-07）。
OCS 系列規則沒有地圖外機場（屬遊戲專屬規則，例如 BTR 的英國基地）。下面是本專案的設計，已記錄可隨時調整。

### 設計

| 項目 | 內容 |
|---|---|
| 表示方式 | 機場與飛機都在**地圖外的 off-map box**（每個攻方一個，名稱如「Axis off-map airfield」），地圖上沒有任何東西。飛機從己方地圖邊緣的進場格飛入：航程 = 到目標最近的己方進場格距離 + 1 格；任務結束回到 box。單位清單、任務與整補畫面顯示「Axis off-map airfield」 |
| 不受攻擊 | 不在地圖上，所以敵方無法砲擊、佔領或縮減；敵方也看不到 box 內容（4.9）。不能 Base Transfer 離開 box（`OFF_MAP_AIRFIELD_TRANSFER`）。box 內的戰鬥機沒有巡邏區、不能攔截（巡邏區以地圖上的機場為中心，14.4c） |
| 容量 | 沒有 Active 飛機上限；整補時所有 Inactive 飛機都可整補 |
| 整補 | 不耗地圖上的 SP，也不受敵方 ZOC 限制（地圖外的補給，比照 12.3e 地圖外 holding box 有自己的補給） |
| 其他規則 | 任務、空戰、攔截、防空、巡邏區（10 格）都照系列規則 |
| 兵力 | 攻守戰的攻方一律有地圖外空軍：Compact 2 戰鬥機＋2 戰術轟炸機，Standard 3＋3，Large 4＋4；與 New Game 的「Air forces」選項無關，選了地圖上空軍則兩者都有 |
| 電腦 | 目前電腦只會整補、不會出任務。S7b 讓電腦（攻方）用空中砲擊支援主攻，S7a 只做規則、生成與 UI |

### 實作紀錄

- 第一版把機場放在攻方地圖邊緣的一格（畫面上看得到），使用者指出「off map 怎麼在場內」，改成真正的地圖外 box。
- 規則：設施類型 `facility:off-map-airfield`（`isOffMapAirfield`）放在 off-map box，同一 box 的己方飛機算駐在該機場（`atOffMapAirfield`）。
  - 航程：`airDistance` = 最近己方進場格到目標的距離 + `OFF_MAP_AIRFIELD_DISTANCE`（1）；任務起點記為該進場格（`airLaunchHex`）。短程右移（14.7c）也用這個距離。
  - 任務：驗證、候選（`readyAircraft`、目標範圍）、空戰／損失、返航都把 box 內的飛機算作在基地；返航時留在 box，通常 Inactive。
  - 整補：來源是機場本身、不扣 SP；上限 99（代表無上限）。
  - 增援：box 內的飛機不算待進場的增援（`arrivingReinforcements`）。
- 生成：OOB 選項 `offMapAir`（攻守戰設為攻方）產生機場（Level 3）與上表的戰鬥機、轟炸機，`staging: 'OFF_MAP_AIRFIELD'`。
  部署放進 `GENERATED_OFF_MAP_AIRFIELD_BOXES[side]`，劇本宣告這個 box（`kind: OFF_MAP`、名稱「… off-map airfield」）。
- UI：
  - 單位清單、任務與整補畫面的位置顯示 box 名稱。
  - 整補面板寫「Off-map airfield · refits every aircraft from its own stocks, no SP · no Active limit」。
  - 任務選項也算 box 內的飛機（原本只看地圖上的飛機，按鈕會是灰的；`tests/ui/off-map-air.test.ts`）。
  - 砲擊段只有飛機能砲擊時，提示改指向 Air 分頁。
  - New Game 說明與預覽提到地圖外空軍。
- 電腦（heuristic@6）：自己的 Movement Phase 砲擊段先用飛機（全部可用的、最多 4 架，含戰鬥機護航）轟炸主攻目標，
  否則轟炸我方單位相鄰的敵方堆疊；再用砲兵打其他格。

## 7. 攻守戰駐守單位調整（2026-10-07）

使用者：「進攻方應該就不需要garrison unit 反之防守方可以多一點」。我一度改成每個目標放 2–3 個駐守單位，使用者反對：
「不須要多個unit 在同一個格. Garrison 只是避免被免費佔領」、「Garrison 也可以適度配置在非vp關鍵點 ex. Supply節點 道路節點」。
最後的做法：
- 攻方本來就沒有駐守單位（駐守單位只放在持有的目標，攻方一個也不持有）。
- 守方每個目標仍是 1 個，另在關鍵點各放 1 個（見 §1 表）。
- 預設 seed 0–2：Axis 進攻時守方 10–12 個目標、另 5–6 個關鍵點；Allied 進攻時 8 個目標、另 4 個關鍵點，多在鐵路城鎮與村莊。
- 測試：`engagements.test.ts`「garrisons in an attack」（攻方 0 個、一格一個、不在目標上、數量上限）。
- 補給（使用者：「是否能在vp放置一定supply 避免守軍因無supply被attrition消滅」，選「每個目標 2T，所有劇本」；
  接著：「防守的ai應該有意識的配合守軍數量增加補給量 或是劇本配置要調整」）：
  - 劇本：每個駐守單位（目標與關鍵點）腳下開局都有 2T 補給堆（`GENERATED_GARRISON_STOCK_TOKENS`）。
    駐守單位被切斷時吃這堆（每回合 1T，12.6c），不必擲消耗；敵方佔領時照佔領表處理（9.14b），擁有者也可先炸掉（12.11a）。
  - 電腦（heuristic@9）：被切斷、補給堆已吃完的駐守單位（MA 0，走不回補給線）也列為補給運送目標。
  - 測試：New Game 組成測試與 smoke 的單位數改為「單位數 + 2 × 目標數」（駐守單位與補給堆）；部署分散測試不計駐守單位與其補給堆。
